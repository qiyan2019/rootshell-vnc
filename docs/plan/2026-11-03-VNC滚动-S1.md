## P（帧缓冲像素 / 远端 point）结论

- **Match Client（adaptive + `.matchClient`）→ P = 2**。依据：`RemoteDisplaySize.matching` 固定 `uiScale = 2` 且要求精确 2× backing（`RemoteDisplaySize.swift:32,66-67,85-86`）；`displaySizingMode` 仅在 `videoQualityMode == .adaptive` 时保留 `.matchClient`（`VNCConfiguration.swift:211-213`），`.matchClient` 生效即虚拟显示器已协商 2×。
- **非 Apple / remoteDisplay → P = 1**：帧缓冲坐标即远端 point。
- **Standard 模式连 Apple 服务端（Retina 物理屏）**：协议侧拿不到 point 维度——`AppleDisplayInfo`（DisplayInfo2）只有像素与 flags，无 point 字段；`AppleVirtualDisplayMode`（客户端发出的 command 29）才携带 point+pixel。此路径默认 P=1，宿主可用 `remotePixelsPerPoint` 覆盖。**待指挥决策：接受 P=1 + override，还是 S4 实测时再定？**
- `resolvedRemotePixelsPerPoint` 优先级：宿主覆盖 > Match Client(2) > 1。

## 残留风险

- 拖动样本速度用 100ms 尾窗估计，手势刚起步时速度偏低 → 前几样本只拿缩放补偿（属预期语义）
- Standard 模式连 Retina Mac 时 P=1 可能欠补偿（见上，待决策）
- `sendFilteredScrollDelta` 的 `.began` 零增量特判在增益后仍成立（0×gain=0），生命周期边界不变
